## Source Code

### `lib/`

All application Dart code. Entry point is `main.dart`; all dependency wiring is in `app_bootstrap.dart`.

```
lib/
├── main.dart                   # App entry point — calls app_bootstrap.dart
├── app_bootstrap.dart          # All DI wiring + 72 named routes (~1600 lines)
├── firebase_options.dart       # Auto-generated Firebase config (do not edit)
├── generated_plugin_registrant.dart  # Auto-generated plugin registry (do not edit)
├── presentation/               # UI layer: screens, BLoCs, shared widgets
├── domain/                     # Business logic: interactors, models, repo interfaces
├── data/                       # Data layer: repository impls, APIs, local storage
└── infrastructure/             # Cross-cutting: auth, services, HTTP, errors, l10n
```

See `architecture.md` for a full breakdown of each layer.

### `test/`

95 test files organized by type:

```
test/
├── unit/       # Pure Dart logic tests (interactors, computation services, mappers)
├── bloc/       # BLoC state machine tests
├── widget/     # Flutter widget rendering tests
├── fixtures/   # Static JSON/data files used as test inputs
├── mocks/      # Generated and manual mock objects
└── infrastructure/  # Tests for services (sync queue, event bus, etc.)
```

Run all tests with:
```bash
flutter test
flutter test --coverage
```

Or use the helper script: `tools/test.sh`

## Platform-Specific Folders

### `android/`

The native Android project that Flutter wraps. Key contents:

```
android/
├── app/
│   ├── src/
│   │   ├── main/
│   │   │   └── AndroidManifest.xml    # App permissions (internet, health, camera, notifications)
│   │   ├── prod/
│   │   │   └── google-services.json   # Firebase config for prod flavor
│   │   └── dev/                       # Dev flavor — no Firebase config
│   └── build.gradle                   # App-level Gradle: versionCode, signing config, flavors
├── build.gradle                       # Project-level Gradle
└── key.properties                     # Keystore credentials (gitignored — generated by Codemagic at build time)
```

**Important:** The signing keystore (`upload-keystore-nn.jks`) and its passwords are stored as encrypted secrets in Codemagic, not in the repository. Codemagic decodes them and writes `key.properties` at build time.

**Flavors:** `dev` and `prod`. Always build and run with `--flavor prod` — the `dev` flavor has no `google-services.json` and Firebase features (FCM, Crashlytics) will not work.

### `ios/`

The native Xcode project. Key contents:

```
ios/
├── Runner/
│   ├── AppDelegate.swift              # Native app delegate (FCM setup)
│   ├── Info.plist                     # App metadata, permissions (camera, health, notifications)
│   └── GoogleService-Info.plist       # Firebase config for iOS (prod)
├── Runner.xcodeproj/                  # Xcode project file
├── Runner.xcworkspace/                # Xcode workspace (use this, not .xcodeproj)
└── Podfile                            # CocoaPods dependencies (generated by Flutter)
```

iOS code signing is handled via App Store Connect API keys configured in Codemagic (`ios_group` environment group). With admin access to Apple Developer, certificates and provisioning profiles can be managed at developer.apple.com.

### `web/`, `linux/`, `macos/`, `windows/`

Platform stubs generated automatically by Flutter. **Not used** — NutRenaissance is a mobile-only app (Android + iOS). These folders exist because Flutter creates them by default but they are not maintained or deployed.

## CI/CD Configuration

### `codemagic.yaml`

Defines the automated build and release pipeline on [Codemagic](https://codemagic.io).

Three workflows:

| Workflow | Trigger | What it does |
|----------|---------|--------------|
| `pr-checks` | Every pull request | `flutter analyze --fatal-infos` + `flutter test --coverage` |
| `android-release` | Push to `master` | Signed AAB → Google Play internal track |
| `ios-release` | Push to `master` | Signed IPA → TestFlight (+ dSYM upload to Crashlytics) |

The two release workflows are configured to trigger on push to `master`; in current operation builds are launched manually from the Codemagic UI under Ion's personal account.

**Signing secrets** are stored as Codemagic environment groups (not in the repo):
- `android_signing`: `CM_KEYSTORE` (base64 keystore), `CM_KEYSTORE_PASSWORD`, `CM_KEY_PASSWORD`, `CM_KEY_ALIAS`
- `ios_group`: `APP_STORE_CONNECT_KEY_IDENTIFIER`, `APP_STORE_CONNECT_ISSUER_ID`, `APP_STORE_CONNECT_PRIVATE_KEY`

### `bitbucket-pipelines.yml`

Runs on Bitbucket on every push. Lighter than Codemagic — only validates, does not build release artifacts:

1. `flutter analyze` — static analysis
2. `flutter test` — unit + widget + BLoC tests
3. Coverage report generation

## Project Configuration Files

### `pubspec.yaml`

The Flutter equivalent of `package.json`. Defines:
- App name, version (`1.1.0+<build>` — see the `version:` field in `pubspec.yaml`), and Dart SDK constraint (`>=3.8.0`)
- All third-party dependencies (Hive, Drift, Amplify/Cognito, Firebase, BLoC, health, ML Kit, LogMeal, etc.)
- Asset paths registered for bundling (`assets/images/`, `assets/svg/`, etc.)
- Custom fonts

Edit this file to add/update/remove packages, then run `flutter pub get`.

### `pubspec.lock`

Auto-generated snapshot of every resolved dependency version. Committed to the repo to ensure all developers and CI use identical package versions. **Never edit manually** — it is updated automatically by `flutter pub get` or `flutter pub upgrade`.

### `analysis_options.yaml`

Dart static analysis rules. Configures which warnings and errors `flutter analyze` enforces. Based on the `flutter_lints` package with any project-specific overrides.

### `dart_test.yaml`

Test runner configuration:
- Default timeout per test
- Tags for filtering test groups
- Concurrency settings for parallel test execution

### `l10n.yaml`

Localization pipeline configuration:
- Input: `.arb` files in `lib/infrastructure/l10n/` (one per language: `app_en.arb`, `app_es.arb`)
- Output: generated Dart classes in `lib/infrastructure/l10n/generated/`
- Supported locales: `en` (English), `es` (Spanish)

Run `flutter gen-l10n` to regenerate after editing `.arb` files (also runs automatically with `flutter run`/`flutter build`).

### `firebase.json`

Firebase project-level configuration. Declares which Firebase services are active for this project (Crashlytics, App Distribution). Used by the Firebase CLI for deployments and by the build toolchain.

### `.fvmrc`

Pins the Flutter SDK version to `3.32.8`. [FVM (Flutter Version Manager)](https://fvm.app) reads this file so all developers use the exact same Flutter version.

```json
{ "flutter": "3.32.8" }
```

If you have FVM installed, `fvm flutter run --flavor prod` uses the pinned version automatically.

## Developer Tools

### `tools/test.sh`

Shell script that wraps `flutter test` with convenient options (coverage output path, test filtering, etc.). Useful for local development when you want the same flags that CI uses.

### `untranslated-messages.txt`

Auto-generated list of localization keys that exist in one language file but are missing from another. Used to track incomplete translations between EN and ES. Generated by `flutter gen-l10n`.

## Key Relationships

```
pubspec.yaml          defines dependencies
    ↓
pubspec.lock          locks exact versions
    ↓
lib/app_bootstrap.dart   wires all dependencies together at runtime
    ↓
codemagic.yaml        builds and signs the app using secrets stored in Codemagic
bitbucket-pipelines.yml  validates code quality on every push
```
